# WorkSphere Security Baseline

## 1. Authentication & Session Security

- **Identity Provider**: Amazon Cognito User Pools (proposed) via OpenID Connect (OIDC) with OAuth 2.0 PKCE (S256).
- **Session Model**: Server-managed session tokens stored in encrypted, signed cookies.
- **Cookie Security Attributes**:
  - `HttpOnly = true` (Inaccessible to client-side JavaScript, mitigating XSS token theft).
  - `Secure = true` (Enforced over HTTPS).
  - `SameSite = Lax` (Mitigating CSRF across origin navigations).
- **Token Validation**:
  - Next.js BFF exchanges authorization code with Cognito over backchannel.
  - Go API independently validates Cognito JWT signatures (`RS256`), issuer, audience, and expiration using cached JWKS.
  - External subject ID (`sub`) is linked to internal WorkSphere user records.

---

## 2. Secrets Management & Repository Hygiene

- **Zero Secret Commits**:
  - No API keys, AWS credentials, Cognito client secrets, database passwords, or private keys may ever be committed to Git.
  - Gitleaks automated scanning is configured in CI and pre-commit hooks to block secrets before push.
  - `.env` files are ignored across the entire repository tree.
- **Environment Placeholders**:
  - `.env.example` provides sanitized variable placeholders with no real credentials or production endpoints.

---

## 3. Defense-in-Depth

- **Network Security**:
  - External traffic enters through AWS ALB or CloudFront with AWS WAF enabled (rate limiting, OWASP Core Rule Set).
  - Go API and PostgreSQL instances are located in private subnets with no public IP assignment.
- **Input Validation**:
  - Frontend input validation using Zod schemas.
  - Backend request validation at handler boundary with strict type checks and limits on payload sizes.
- **SQL Injection Prevention**:
  - All database queries are generated by `sqlc` with parameterized SQL (`$1, $2, ...`). Dynamic raw string concatenation in SQL queries is strictly prohibited.
- **Container Security**:
  - Minimal container base images (`alpine` or `distroless`).
  - Containers run as non-root unprivileged users (`USER 10001:10001`).
  - Container vulnerability scanning via Trivy.
- **Sri Lankan Regulatory Compliance & Privacy**:
  - WorkSphere operates in alignment with the Sri Lanka Personal Data Protection Act (PDPA), No. 9 of 2022.
  - Formal regulatory compliance certifications (e.g. ISO 27001, SOC 2, IRD electronic invoicing validation) remain subject to formal operational audit in production rollout phases.
